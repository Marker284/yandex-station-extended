# JBL Link Portable: ADB, SSH и автозапуск

Для версии с Алисой, quasar `1.80.0.228.3676569159.20251219.`, ARMv7,
Yocto/systemd. [Пошаговая инструкция](../../docs/start/root-jbl-link-portable.md).

| Файл | Назначение |
|---|---|
| `enable-adb.sh` | Создать и защитить два постоянных маркера ADB |
| `ota-guard.sh` | Блокировать запись в известный каталог OTA и проверить её |
| `install-ssh.sh` | Установить проверенные Dropbear и публичный ключ в новый каталог |
| `ssh-service.sh` | Управлять key-only Dropbear через временный systemd-unit |
| `fluent_bootstrap.c` | Исходник ARMv7-плагина штатного Fluent Bit 1.4.6 |
| `build.py` | Собрать плагин локально clang/ELF lld, без Linux sysroot |
| `install-autostart.py` | Добавить include в конфиг из `/data`, сохранить оригинал и отключение |
| `bootstrap.sh`, `run.sh` | Воссоздать runtime-unit и выполнить короткие startup-скрипты |
| `hooks.d/` | Запуск SSH и маркер выполнения в конкретной загрузке |

Ни один установщик не меняет размеры разделов, томов или содержимое rootfs.
Установка SSH отказывается работать поверх существующего `/data/jbl-ssh`.
Автозапуск также отказывается заменять существующий `/data/jbl-autostart`.
Оригинал изменяемого device.cfg сохраняется на колонке и в локальном `private/`.
Этот файл содержит идентификатор устройства: не включать его в коммиты.

## Сборка плагина

Нужны Python 3.9+, clang с ARM target и ELF lld. Команда из корня репозитория:

```sh
python3 contrib/jbl-link-portable/build.py --clang clang --lld ld.lld
```

На macOS при отсутствии ld.lld в PATH скрипт также умеет использовать установленный
Rust toolchain с его libLLVM. Результат — `build/flb-in_jbl_bootstrap.so`, ELF32 ARM,
hard-float. Это динамический плагин для конкретного Fluent Bit, не отдельная программа.
Используется публичная ABI-структура input из
[Fluent Bit 1.4.6](https://github.com/fluent/fluent-bit/blob/v1.4.6/include/fluent-bit/flb_input.h).

Установленные на проверенной колонке Dropbear/dropbearkey — статические ARMv7
файлы из `contrib/bin`; установщик проверяет их SHA-256 перед выполнением.
Ключ сервера создаётся для каждого экземпляра отдельно, приватный ключ клиента
на колонку не передаётся. Парольный вход выключен.

## Проверки и ограничения

На колонке проверены маркеры ADB, блокировка записи в `/bkupgrade`, ключевой SSH,
плагин, перезапуск штатного сборщика логов и полный reboot. После reboot прямой
SSH заработал без старта с компьютера; marker совпал с новым boot_id, systemd
сообщил успешное выполнение hooks. Службы Алисы и сборщика логов остались активны.

`install-ssh.sh` оформляет ту же последовательность отдельной обёрткой; повторная
первичная установка этой обёрткой на рабочую колонку не выполнялась.
Изменения упаковки проверяются локально, а не повторной установкой поверх ключей.

Офлайн-проверка отказа до подключения или записи при неподходящем плагине/прошивке:

```sh
python3 contrib/jbl-link-portable/test_offline.py
```

Автозапуск зависит от штатного logs.cfg: в режиме idle.cfg плагин не загружается.
Не отключать fluent-bitd как «лишнюю телеметрию», если нужен этот автозапуск.
Хук не создаёт лог-записей и не добавляет отправку данных. Отключение:

```sh
sh /data/jbl-autostart/rollback.sh
```

Эта команда выполняется на колонке, возвращает оригинальные байты device.cfg
и оставляет установленные файлы и действующий SSH. Фактическое отключение
рабочей установки ради теста не выполнялось; скрипт содержит проверки хешей.

# Как дополнять вики

Вики открыта для сообщества. Исследовали свою колонку, сняли дампы, написали скрипт —
добавьте материал сюда.

## Самый простой способ — в браузере

На сайте есть свой редактор: git знать не нужно, нужен только аккаунт GitHub.

1. Откройте статью на сайте [hackalice.me](https://hackalice.me) и нажмите ✏️ над
   заголовком или «Править эту страницу» внизу. Если выделить кусок текста, появится
   кнопка «Предложить правку» — редактор откроется сразу на этом месте.
2. Войдите через GitHub. Права на репозиторий не нужны: редактор сам сделает форк и ветку.
3. Правьте Markdown слева, справа — превью в стилях сайта. В панели над текстом есть
   заметки, вкладки, таблицы и блоки команд, картинки вставляются из буфера.
4. Нажмите **«Отправить правку»**, опишите, что изменилось и на чём проверено.
   Получится Pull Request от вашего имени.
5. Мы проверим правку и примем её — сайт обновится автоматически (обычно за минуту).
   Если попросим что-то поправить, откройте страницу снова: правка уйдёт в тот же PR.

Новую страницу — кнопкой «Новая страница» внизу любой статьи: выберите раздел и заголовок,
пункт в меню добавится сам. Строку в таблицу своего раздела допишем при ревью.

!!! warning "Личные данные"
    Редактор не даст отправить текст, похожий на ключи из `devices.json`, токены и MAC-адреса.
    Замените их на `<DEVICE_ID>` или `<REDACTED>`.

Только сообщить об ошибке, без правки, — ссылка «Только сообщить об ошибке» внизу статьи
или кнопка «Ошибка» над выделенным текстом: откроется issue с адресом страницы и цитатой.

!!! note "Если редактор недоступен"
    Когда редактор отключён или не отвечает, карандаш открывает веб-редактор GitHub на том же
    файле: правьте Markdown и нажмите **Propose changes** — получится такой же Pull Request.

## Куда добавлять материалы

| Тип материала | Куда |
|---|---|
| Получение и закрепление доступа, восстановление | `docs/start/` |
| Готовый рецепт («как сделать X») | `docs/recipes/` + строка в `docs/recipes/index.md` + пункт в `nav` в `mkdocs.yml` |
| Железо конкретной модели | `docs/devices/<модель>.md` |
| Новая модель | новый файл в `docs/devices/` + строка в `docs/devices/index.md` + пункт в `nav` в `mkdocs.yml` |
| Как устроена прошивка, сеть, сборка софта | `docs/internals/` |
| Скрипты и бинарники | `contrib/` |
| Длинные дампы: `i2cdump`, карта разделов, лог загрузки | файлом в `contrib/dumps/`, со ссылкой со страницы модели |

Порядок внутри страницы-инструкции: **сначала шаги, потом «как это работает»**.
Пишите только то, что проверили сами, и указывайте, на какой модели и прошивке.

Общее для всех Станций на Amlogic описывается в разделе «Как это устроено», особенности
корпуса и платы — в «Устройствах».

## Минимальный набор данных для новой модели { #new-model }

Если на руках модель, которой ещё нет в таблице поддержки, подключитесь к ней командой
`adb shell` и снимите диагностику:

```sh
echo "=== MODEL & KERNEL ==="
cat /proc/device-tree/model
uname -a
echo "=== CPU ==="
cat /proc/cpuinfo | grep -E 'processor|part|Hardware|model name'
echo "=== MEMORY & STORAGE ==="
cat /proc/meminfo | head -2
cat /proc/mtd
df -h
echo "=== I2C & PERIPHERY ==="
ls /sys/bus/i2c/devices/
ls /sys/class/leds/
cat /proc/asound/cards
echo "=== QUASAR VERSION ==="
cat /system/vendor/quasar/VERSION 2>/dev/null
```

Выводом поделитесь в [issue репозитория](https://github.com/Marker284/yandex-station-extended/issues)
или в pull request — страницу модели оформим сами.

## Что нельзя публиковать

По этим данным находят владельца и его дом, поэтому публиковать их нельзя:

- приватные ключи устройства — `server_private_key` и `secret` из `/data/quasar/devices.json`;
- настоящие MAC-адреса, серийные номера и `device_id`;
- OAuth-токены аккаунтов Яндекса;
- пароли, имена домашних сетей Wi-Fi и координаты.

Вместо них подставляйте `<DEVICE_ID>` и `<REDACTED>`.

## Локальный запуск

Чтобы смотреть правки у себя:

=== "Linux и macOS"

    ```sh
    git clone https://github.com/Marker284/yandex-station-extended.git
    cd yandex-station-extended
    python3 -m venv venv
    ./venv/bin/pip install -r requirements.txt
    ./venv/bin/mkdocs serve
    ```

=== "Windows (PowerShell)"

    ```powershell
    git clone https://github.com/Marker284/yandex-station-extended.git
    cd yandex-station-extended
    py -m venv venv
    .\venv\Scripts\pip install -r requirements.txt
    .\venv\Scripts\mkdocs serve
    ```

Сайт откроется на `http://127.0.0.1:8000` и обновится при каждом сохранении файла.
Перед отправкой полезно прогнать `mkdocs build` и `contrib/wikilint.py` — но если они
не запускаются, присылайте правку как есть, оформление поправим сами.

Как писать текст — в [правилах
оформления](https://github.com/Marker284/yandex-station-extended/blob/main/STYLE.md),
как оформить pull request — в
[CONTRIBUTING.md](https://github.com/Marker284/yandex-station-extended/blob/main/CONTRIBUTING.md).

Все, чьи правки и данные вошли в вики, перечислены на странице [Участники](contributors.md).

# Подводные камни

Неочевидные вещи, на которые реально натыкались при работе со Станцией Лайт.

## Файловая система

- **`/` только для чтения.** Правки: `mount -o remount,rw /` → правка → `sync` →
  `mount -o remount,ro /`.
- **Без `sync` правки теряются.** UBIFS держит записи в памяти; при зависании или выдёргивании
  питания только что записанный файл может исчезнуть целиком. После любых важных правок — `sync`.
- **`sync` может зависнуть**, если в ядре застрял упавший `mount` (например, после oops
  драйвера ФС). Тогда сбрасывайте конкретные файлы через `fsync` и перезагружайтесь по питанию.

## BusyBox

- нет `timeout`;
- `awk` без математики (`exp`, `log` → «Math support is not compiled in»);
- `tar` без `-z` (используйте `gunzip -c | tar -x`);
- `test -w` говорит «можно писать» даже на read-only разделе — проверяйте режим монтирования
  в `/proc/mounts`;
- `sync` не принимает аргументы;
- урезанный `lsusb` (только ID без названий) — полноценный ставится `yse install usbutils`.

## Звук (ALSA)

- **Работающие плееры не видят правки `/etc/asound.conf`.** alsa-lib перечитывает конфиг,
  только если изменился главный `/usr/share/alsa/alsa.conf`, а `asound.conf` подключается из
  него хуком. После правки: `touch /usr/share/alsa/alsa.conf`.
- **`softvol` создаёт регулятор на карте своего выхода.** Если выход — не `card0`, появится
  второй `Master`, и кнопки громкости перестанут работать. Указывайте `card 0` в `control { }`.

## Автозапуск и hotplug

- `mdev -d` читает `/etc/mdev.conf` один раз при старте: новые правила работают после перезапуска
  `mdev` или перезагрузки. Шаблон сравнивается с `DEVNAME` целиком, например `snd/controlC1`.
- `/sbin/hotplug` нет — события обрабатывает только демон `mdev`.

## Отладка падений

- Причина последней перезагрузки: `cat /sys/class/aml_info/reboot_reason`.
- `pstore` очищается при обычной загрузке (`S98pstore-clear`) — лог ядра ловите вживую:
  `ssh … 'cat /proc/kmsg'`.
- Логи демонов: `/data/quasar/daemons_logs/` (`maind.log`, `mediad.log`, `yiod.log` …).

## Память и ядро

- `devmem` (mmap `/dev/mem`) работает, а `read()` из `/dev/mem` возвращает 0 байт.
  `/dev/kmem` не читает образ ядра.
- Модули ядра: подпись (vermagic) у Яндекса — `4.9.y`, хотя `uname -r` = `4.9.68`. Но даже с
  правильной подписью модули из чистых исходников опасны: `struct task_struct` у Яндекса
  другая. Подробности — [USB Host → модули](../recipes/usb-host.md).

## Сеть

- В `quasar.cfg` есть сторож Wi-Fi (`wifiReseter`) и проверка связи `generate_204`.
- Есть запасные адреса DNS (`DnsFallbackMap`) — см. [Сеть](network.md).

## glagol: когда порт 1961 молчит { #glagol-1961 }

- **`:1961` поднимается только после успешного `/glagol/device_list`** из облака. Список
  устройств кэшируется лишь в памяти процесса. Поэтому при холодной загрузке с доступным
  бэкендом порт открывается, а после краха/рестарта `maind` **без связи с облаком** — нет
  (`account_devices.cpp: Fail to update account device list: Timeouted`), хотя mDNS его уже
  рекламирует, а внутренний `127.0.0.1:9899` работает.
- Когда связь возвращается, в логе видно `glagol_ws_server.cpp: Restarting WS server due to new
  auth data. Settings.port = 1961` — порт несколько раз мигает и затем встаёт стабильно. Строки
  `asio async_shutdown error: ... SSL_shutdown` — безобидный шум отвалившихся коннектов.
- **Битый `conversationToken` роняет `maind --platformd`** целиком (его поднимет
  `quasar_launcher2`). Корректный клиент шлёт валидный JWT и проблемы не создаёт — но при
  фаззинге `:1961` держите это в уме. Детали протокола — [Сеть → glagol](network.md#glagol).

# Своя LLM вместо Алисы

!!! note "Варианты подключения"
    [Quasar Bridge](#quasar-bridge) позволяет подключить свою LLM и Home Assistant,
    сохранив облачный речевой тракт и часть функций Яндекса.
    [quasard](#quasard) предлагает собственный бэкенд с заменой распознавания и синтеза речи.
    [Alisa-ChatGPT-voice-assistant](#chatgpt-web) переключает колонку в голосовой режим
    веб-версии ChatGPT через Linux-ПК.

**Цель:** отвечать на общие вопросы своей моделью (ChatGPT, Claude, Ollama).
Сохранение умного дома, музыки, таймеров и голоса Алисы зависит от выбранного способа.

## Что известно

- Голосовые запросы колонка отправляет не обычным HTTP-запросом к `backendUrl`, а по
  отдельному соединению с «uniproxy». Его адрес задаётся ключами `uniProxyUrl` и
  `uniProxyQuicUrl` в `/system/vendor/quasar/quasar.cfg` (ключи есть в прошивке Лайт 3.21).
- `quasar.cfg` лежит на rootfs, его можно править после `mount -o remount,rw /`.

!!! tip "Как устроен голосовой тракт"
    Разбор потока (локальные спотеры → `uniproxy`, protobuf Alice API, события `AsrResult`/
    `AliceResponse`/`TtsSpeak`, TTS) есть на странице [Голосовой тракт Алисы](../internals/voice.md).
    Там же, в конце, написано, что это значит для своего ASR/LLM.

## Голосовой режим веб-версии ChatGPT { #chatgpt-web }

[Alisa-ChatGPT-voice-assistant][chatgpt-bridge] — аудиомост между микрофонами и динамиком
Станции и официальным сайтом ChatGPT. Сайт работает в Chromium на виртуальном экране
Xvfb, без окна на рабочем столе. В этом режиме отвечает голос ChatGPT.

### Как подключить { #chatgpt-web-setup }

1. Подготовьте Лайт 2 с уже работающим root и SSH по ключу, доступную Linux-ПК.
   Проверена **YNDX-00028 / Plum**, прошивка
   `0.369.1.50.4794654278.20261021.133`, CachyOS с PipeWire-Pulse.
2. Установите зависимости и соберите ARM32-модули по [README проекта][chatgpt-bridge].
   Нужны Python 3.11+, Chromium, Xvfb, xauth, OpenSSH, ALSA utilities, Clang и LLD;
   на колонке — штатный Quasar и `socat`.
3. Настройте SSH-псевдоним `alice`, проверьте ключ хоста и запустите мост на ПК:

    ```sh
    python3 bridge.py start
    ```

4. По инструкции проекта один раз войдите на `chatgpt.com` в отдельном профиле Chromium
   и закройте окно входа. Нужен аккаунт с доступным голосовым режимом.
5. Произнесите команду переключения:

    | Команда | Действие |
    |---|---|
    | «Алиса, открой чат» | голосовой режим предыдущего разговора ChatGPT |
    | «Алиса, создай новый чат» | новый разговор |
    | «Алиса, закрой чат» | завершение ChatGPT и возврат к обычной Алисе |

Для завершения из терминала:

```sh
python3 voice.py close
```

### Как работает и что требуется { #chatgpt-web-limits }

- Linux-ПК нужен всё время работы моста. На нём работают Chromium и виртуальные
  аудиоустройства; на колонке — вспомогательные процессы передачи звука и команд.
- Команды переключения распознаёт штатное **облако Яндекса**. Отдельный Vosk не нужен,
  но без интернета на колонке голосовой выход из GPT не гарантируется.
- Обычная Алиса доступна после выхода из чата. Во время GPT её ответы подавляются,
  штатная музыка ставится на паузу. Команду закрытия произносят в паузе между ответами:
  во время собственного звука мост отклоняет новые пробуждения Алисы.
- Это отдельный режим ChatGPT, а не маршрутизация каждого запроса между Яндексом и LLM.
  Временный профиль запуска Quasar подключает аудиомодули; адрес `uniProxyUrl`
  для этого проекта не меняется.
- Вход и лимиты голосового режима определяются сайтом ChatGPT. Браузерный профиль
  с сессией хранится на ПК; изменения интерфейса сайта могут потребовать обновления моста.
- Доступны [обработанный микрофон VQE](microphone.md) и
  [радужная подсветка Plum](led.md#plum-led). Совместимость других моделей не проверена.

[chatgpt-bridge]: https://github.com/rison1337/Alisa-ChatGPT-voice-assistant

## Quasar Bridge

[Quasar Bridge](https://github.com/skrashevich/quasar-bridge) — прокси на Go,
который распределяет запросы колонки между своей LLM, Home Assistant и Яндексом.
Распознавание речи и озвучивание ответов остаются облачными, с голосом Алисы.

### Как подключить

1. Получите root и SSH-доступ к колонке. Проверена **Станция 2, Quasar 3.21,
   Linux 4.9.68, ARM64**; совместимость других моделей и прошивок нужно проверять отдельно.
2. Выберите способ запуска: отдельный хост или сама колонка через
   [YAM](yam.md). Готовые `.yap` для Linux ARM64 и файлы SHA256 опубликованы в
   [релизах](https://github.com/skrashevich/quasar-bridge/releases).
3. Укажите в конфиге OpenAI-совместимый API и модель. Для управления домом
   подключите совместимый [HA MCP](https://github.com/homeassistant-ai/ha-mcp).
   Настройте правила маршрутизации под свои запросы.
4. Направьте `uniProxyUrl` и `uniProxyQuicUrl` колонки на Go-сервер по
   [инструкции](https://github.com/skrashevich/quasar-bridge#readme).
   Установка пакета YAM сама по себе речевой endpoint не переключает.

### Как распределяются запросы

В примере конфигурации используются три маршрута:

| Запрос | Обработчик |
|---|---|
| Управление устройствами и вопросы об их состоянии | Home Assistant; ответ формулирует своя LLM |
| Сложные вопросы, явное «спроси нейросеть», чтение веб-страниц и истории | Своя LLM |
| Музыка, погода, таймеры и обычные облачные функции | Яндекс |

Правила и поведение для несовпавших запросов задаются в JSON-конфиге;
их можно перечитать без пересборки сервера. Поддерживается переход к своей LLM
после распознанного отказа облачной Алисы.

Для последовательных локальных вопросов сохраняется контекст диалога.
У LLM есть инструменты чтения веб-страниц по URL, поиска по журналу запросов
и ответов, получения текущего времени. Журнал включается отдельно и по умолчанию выключен.

### Ограничения

- Доступ к Яндексу и привязка колонки к аккаунту сохраняются: ASR и TTS работают
  через облако даже при локальном ответе.
- Запуск прокси на колонке не означает запуск на ней LLM или Home Assistant:
  их API должны быть доступны по сети.
- Пакет `.yap` предназначен для ARM64. Установка и голосовой тракт проверены
  на Станции 2; поддержки всех Станций это не гарантирует.
- Для медленных локальных ответов есть настраиваемое беззвучное ожидание,
  которое поддерживает речевой поток дольше начального тайм-аута. Общий лимит
  обработки запроса сохраняется.

## quasard

!!! info "От автора — [@amirilivice](https://github.com/amirilivice)"
    Репозиторий: **[amirilivice/quasard](https://github.com/amirilivice/quasard)**.
    Неофициальный проект, с Яндексом не связан. Только для своих устройств и в
    исследовательских целях.

Готовый бэкенд, который полностью заменяет облако Алисы. Колонка думает, что говорит с
Яндексом, но активация, голосовой цикл и музыка идут через ваш сервер, наружу станция больше
не ходит. Название — от внутреннего имени бэкенда умных устройств Яндекса (quasar).

### Как устроено

```text
Яндекс Станция ──DNS доменов Яндекса → ваш сервер──> quasard
                                                      │
       HTTP (oauth / quasar / метрики)  ◄────────────┤  мок активации и конфигурации колонки
                                                      │
       WebSocket uniproxy (/uni.ws)     ◄────────────┘  голосовой цикл:
         микрофон Ogg/Opus → Silero VAD (конец фразы) → GigaAM (речь в текст)
         → LLM (стриминг ответа по фразам) → F5-TTS (голос) → Ogg/Opus на колонку
```

- **Активация без облака.** Сервер сам отвечает на oauth, `register`, `get_sync_info`,
  `device_list` и метрики. Обновления прошивки заблокированы, чтобы колонка не обновилась
  на версию, которая всё сломает.
- **Оба протокола uniproxy.** На прошивках ~1.56 это JSON, на 3.x бинарный protobuf `AAPI`.
  Формат сервер определяет по первому кадру. Схемы для 3.x восстановлены из прошивки и
  лежат в `alice_server/aliceapi.desc`.
- **Распознавание:** GigaAM v3 (`v3_e2e_rnnt`, сразу с пунктуацией) плюс Silero VAD для
  конца фразы. Занимает около 1 ГБ видеопамяти.
- **Ответы:** любой OpenAI-совместимый API (Groq, Ollama, vLLM, LM Studio…), с историей
  диалога. Характер задаётся в файле `system_prompt.txt` (создаётся рядом с конфигом),
  он перечитывается на лету.
- **Стриминг по фразам.** Ответ LLM режется по знакам препинания. Первая готовая фраза
  сразу озвучивается и уходит на колонку, пока модель дописывает остальное, поэтому станция
  начинает говорить почти без паузы.
- **Голос:** клон по 10–15-секундному образцу на F5-TTS (русские веса ESpeech, ~3.4 ГБ
  видеопамяти). Запасной вариант без GPU — Edge TTS.
- **Музыка** из Яндекс Музыки: «Моя волна», поиск по исполнителю/треку/альбому, «дальше»,
  «назад», лайк/дизлайк, пауза, «что сейчас играет».
- **Быстрые команды** без LLM: громкость, «стоп», bluetooth, сброс диалога.

### Чем отличается от цели этой страницы

quasard не проксирует запросы в облако Яндекса, а **заменяет его целиком**. Поэтому:

- голос свой (клон или Edge TTS), а не Алисы;
- облачного умного дома и сценариев Яндекса нет: из «навыков» есть музыка и быстрые команды;
- зато всё работает локально, без аккаунта в облаке Алисы и без интернета (кроме LLM-API и
  музыки, если они облачные).

Гибрид «своя LLM для болтовни + облако для остального» на базе quasard сделать можно:
сервер уже разбирает оба протокола uniproxy и видит распознанный текст. Не хватает
только проксирования остальных запросов в настоящий uniproxy.

### Что понадобится

- Windows или Linux, видеокарта NVIDIA (проверялось на RTX 5080, 16 ГБ); Python 3.12,
  [uv](https://github.com/astral-sh/uv), ffmpeg.
- Роутер, на котором можно увести домены Яндекса на свой ПК (у автора — OpenWrt), принудительный
  DNS и сертификат, которому доверяет колонка. Подробно, с примерами для OpenWRT, в
  [docs/TRAFFIC_CAPTURE.md](https://github.com/amirilivice/quasard/blob/main/docs/TRAFFIC_CAPTURE.md).
- Ключ к LLM-API (по умолчанию бесплатный Groq) или локальная модель.

Быстрый старт из клона репозитория (подробнее — в
[README](https://github.com/amirilivice/quasard#readme), там же `start.ps1` для Windows):

=== "Windows"

    ```bat
    uv venv -p 3.12 .venv
    uv pip install -p .venv torch torchaudio --index-url https://download.pytorch.org/whl/cu128
    uv pip install -p .venv -r requirements.txt
    copy config.example.toml config.toml
    .venv\Scripts\python -m alice_server
    ```

=== "Linux"

    ```sh
    uv venv -p 3.12 .venv
    uv pip install -p .venv torch torchaudio --index-url https://download.pytorch.org/whl/cu128
    uv pip install -p .venv -r requirements.txt
    cp config.example.toml config.toml
    .venv/bin/python -m alice_server
    ```

Сервер слушает порты 80 (HTTP) и 443 (HTTPS) — на них DNS роутера и уводит домены Яндекса.

Проверить без колонки можно имитаторами: `tools/activation_sim.py` (активация),
`tools/station_sim.py --text "Привет"` (диалог), `tools/fake_llm.py` (LLM без ключа).

### Ограничения

- Прямые ссылки Яндекс Музыки отдаются через редирект. Сервер проходит его за колонку,
  потому что плеер старой прошивки редиректы не любит.
- Скорость и качество голоса зависят от GPU: на слабой карте первая фраза приходит
  с задержкой ~1–2 с.
- Бесплатные тарифы LLM-API ограничены по числу запросов в день.

## Исследования и совместимость

- Протокол uniproxy: какие сообщения идут в обе стороны и как отличить «болталку» от
  команд умного дома. *(Основное описано в [Голосовом тракте](../internals/voice.md). Рабочий
  разбор JSON и protobuf-кадров `AAPI` есть в [quasard](#quasard): `alice_server/uniproxy.py`,
  `alice_server/aliceapi.desc`.)*
- Как подставить свой текст в ответ, чтобы его озвучила Алиса. *(Локально — через API glagol,
  как интеграция YandexStation для Home Assistant, см. [Сеть → glagol](../internals/network.md#glagol).
  При полной замене бэкенда, как в quasard, озвучивает уже свой TTS, не голос Алисы.
  [Quasar Bridge](#quasar-bridge) возвращает локальные ответы через облачный TTS Яндекса.)*
- Как прошивка проверяет сервер (TLS, сертификаты) при подмене адреса. *(Пиннинга нет, см.
  [Подводные камни](../internals/gotchas.md); работает и `ws://` без TLS.)*
- Совместимость гибридного прокси с разными моделями и прошивками. Рабочий пример —
  [Quasar Bridge](#quasar-bridge): свои LLM и Home Assistant, облачный речевой тракт
  и проксирование остальных запросов в Яндекс; проверен на Станции 2 с Quasar 3.21.

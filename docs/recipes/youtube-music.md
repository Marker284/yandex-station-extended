# YouTube Music голосом, с телефона и из браузера

[ytm-alice](https://github.com/SPAWNRYS-ban/ytm-alice) играет YouTube Music на самой колонке:
«Алиса, включи на ютубе …», веб-панель в браузере и трансляция из приложения YouTube Music
на телефоне. Компьютер и вход в Google не нужны, лайки и плейлисты — по желанию. Штатная
Алиса и кнопка паузы продолжают работать.

**Проверено на:** Станция Мини 2 (`yandexmini_2`), quasar 3.21, ytm-alice 0.7.2-hotfix и сборка
из ветки `main`, YAM 0.2.5, ноябрь 2026. Станцию Лайт 1 (`yandexmicro`) проверял автор проекта.
Пакетов под другие модели нет.

## Что понадобится { #requirements }

- root и SSH на колонке — [получение root](../start/index.md#root-by-model), [SSH](../start/ssh.md);
- YAM 0.2.x на колонке — [проект YAM](https://github.com/nyakokitsu/yam), установщик из
  его README;
- около 20 МБ свободного места в разделе данных;
- доступ колонки к YouTube. Если провайдер его режет, нужен обход на роутере или
  [alice-zapret2](https://github.com/lr1ne/alice-zapret2). (## Ошибка «YouTube Music: network unavailable» {#network-unavailable}

Сервис запущен, веб-панель открывается, но `ytm-alice play` и голосовые команды отвечают `YouTube Music: network unavailable`. При этом обход блокировок (zapret2 / alice-zapret2) запущен и `hosts.txt` содержит нужные домены.

### Причина

DNS-сервер роутера (или провайдера) не резолвит `music.youtube.com`: на запрос приходит `NXDOMAIN`, хотя внешние DNS (`8.8.8.8`, `1.1.1.1`) домен отдают. `ytm-alice` ходит на этот домен за поиском и очередью, поэтому без резолва он сообщает, что сети нет. Zapret2 тут не виноват: он обрабатывает TLS, а до TLS дело не доходит.

Косвенные признаки: `curl` к `music.youtube.com` то работает (из кэша), то падает с `exit=6`; `nslookup` отвечает `server can't find music.youtube.com: NXDOMAIN`.

### Диагностика

Подключитесь по SSH (`ssh -p 2222 root@<IP колонки>`).

**1. Проверьте, что обход запущен и правила на месте:**

```
ps | grep nfqws
iptables -t mangle -S | grep -i nfqueue
```

**2. Проверьте DNS несколько раз подряд и на внешних серверах:**

```
cat /etc/resolv.conf
nslookup music.youtube.com
nslookup music.youtube.com 8.8.8.8
nslookup music.youtube.com 1.1.1.1
```

Если роутер отвечает `NXDOMAIN`, а `8.8.8.8` и `1.1.1.1` дают адреса, причина именно в DNS роутера.

**3. Проверьте доступность хостов по коду выхода `curl`:**

```
cat > /data/tmp/t.sh <<'EOF'
for h in "$@"; do
  curl -4 -sS -m 8 -o /dev/null https://$h/ 2>/dev/null
  echo "$h exit=$?"
done
EOF
sh /data/tmp/t.sh www.youtube.com music.youtube.com i.ytimg.com youtubei.googleapis.com redirector.googlevideo.com
```

| `exit` | Что значит                                                     |
| ------ | -------------------------------------------------------------- |
| 0      | хост доступен                                                  |
| 6      | не резолвится, проблема с DNS                                  |
| 28     | таймаут: пакеты не доходят, часто из-за IPv6 без маршрута      |
| 35, 56 | сброс соединения (DPI), стратегия обхода не подходит           |

!!! note "Не путайте с IPv6"
    `curl` без `-4` сначала пробует IPv6, и при его отсутствии виснет с `exit=28`. Для проверки всегда используйте `-4`. Отключение IPv6 на колонке в этом случае не помогло.

### Решение

Сделайте так, чтобы колонка резолвила имена через рабочий DNS.

**Вариант 1: на роутере (предпочтительно).** Смените upstream DNS на `1.1.1.1` и `8.8.8.8`, лучше через DoH или DoT: провайдеры часто подменяют ответы по UDP/53. Проверьте, что на роутере нет DNS-фильтра или блоклиста, который режет `youtube.com`.

**Вариант 2: на самой колонке.**

```
cp /etc/resolv.conf /data/tmp/resolv.bak
printf 'nameserver 1.1.1.1\nnameserver 8.8.8.8\n' > /etc/resolv.conf
```

Файл создаёт `dhcpcd` и может перезаписать его при перезагрузке. Чтобы правка пережила рестарт, положите её в `/etc/resolv.conf.head` или в свой скрипт автозапуска.

### Проверка

```
nslookup music.youtube.com
ytm-alice play "Daft Punk Get Lucky"
```

В выводе `nslookup` должны быть адреса вида `142.251.x.4`, а `ytm-alice` должен начать воспроизведение.

### Если остался `exit=35` или `56`

DNS в порядке, но соединение сбрасывается. Тогда стратегия zapret2 не подходит провайдеру: подберите другую через `blockcheck2.sh` из репозитория [zapret2](https://github.com/bol-van/zapret2) на компьютере в той же сети и перенесите параметры в `nfqws2` на колонке.

### Дубли правил iptables

Если `iptables -t mangle -S | grep -c NFQUEUE` показывает больше двух правил (по одному на порты 80 и 443), zapret2 запускали несколько раз подряд без остановки. Остановите его (`/etc/init.d/S99zapret2 stop`), убедитесь, что счётчик упал до 0, и запустите один раз)

## Установка { #install }

1. Скачайте из [последнего релиза](https://github.com/SPAWNRYS-ban/ytm-alice/releases/latest)
   пакет для своей модели и файл с его суммой:

    | Модель | Пакет |
    |---|---|
    | Станция Лайт 1 | `ytm-alice-<версия>-yandexmicro.yampkg` |
    | Станция Мини 2 | `ytm-alice-<версия>-yandexmini_2.yampkg` |

2. Сверьте сумму:

    ```sh
    sha256sum -c ytm-alice-0.7.2-hotfix-yandexmini_2.yampkg.sha256
    ```

3. Скопируйте пакет на колонку:

    ```sh
    scp -P 2222 ytm-alice-0.7.2-hotfix-yandexmini_2.yampkg root@<IP колонки>:/data/tmp/
    ```

4. На колонке установите пакет и включите автозапуск:

    ```sh
    yam install --yes /data/tmp/ytm-alice-0.7.2-hotfix-yandexmini_2.yampkg
    /data/yam/bin/ytm-alice daemon install
    rm /data/tmp/ytm-alice-*.yampkg
    ```

5. Проверьте, что сервис отвечает:

    ```sh
    ytm-alice web status
    ```

    В выводе — адрес веб-панели, `http://<IP колонки>`.

Обновление — те же шаги с новым пакетом. Перед установкой остановите сервис командой
`ytm-alice daemon stop`. Очередь и вход в аккаунт сохраняются.

## Использование { #usage }

### Голосом { #voice }

| Фраза | Что происходит |
|---|---|
| «Алиса, включи на ютубе X», «поставь в ютубе X» | поиск и воспроизведение |
| «Алиса, включи песню X», «поставь трек X» | то же без слова «ютуб» |
| «Алиса, поставь альбом X» / «плейлист X» | альбом или плейлист |
| «Алиса, включи мои лайки» | понравившиеся, нужен вход в аккаунт |
| «Алиса, пауза / продолжи / следующий трек / предыдущий трек / стоп» | управление |
| «Алиса, что сейчас играет» | название трека |

Перед треком Алиса говорит «Включаю». Отключается командой `ytm-alice announce-off`.

### Веб-панель { #web }

Откройте `http://<IP колонки>` в браузере любого устройства в той же сети. В панели — поиск,
очередь и управление воспроизведением. Для лайков и личных плейлистов импортируйте cookies
YouTube в настройках панели, инструкция по экспорту — там же. Поиск и воспроизведение
работают и без аккаунта.

### С телефона { #cast }

Колонка видна в приложении YouTube Music как телевизор:

1. Подключите телефон к той же сети Wi-Fi, что и колонку.
2. Нажмите в приложении значок трансляции и выберите колонку.

С телефона работают очередь, пауза, переключение треков и громкость. Колонка отвечает на
поиск устройств по SSDP и принимает подключение на порту `8008`. Имя в списке устройств
задаёт переменная `YTM_ALICE_CAST_NAME`, выключает приём `YTM_ALICE_CAST=0`.

Трансляция есть в ветке `main` проекта, в релизе 0.7.2-hotfix её нет.

### С консоли { #cli }

```sh
ytm-alice play "Daft Punk Get Lucky"
ytm-alice search "ambient"
ytm-alice select 2
ytm-alice pause
ytm-alice next
ytm-alice status
```

Полный список команд и клиент для компьютера — в
[документации CLI](https://github.com/SPAWNRYS-ban/ytm-alice/blob/main/docs/CLI.md) проекта.

## Ограничения { #limits }

- **YouTube отвечает 429 на общих IP.** Если провайдер выпускает абонентов через общий адрес
  (CGNAT), после нескольких переключений трека YouTube перестаёт отдавать потоки на время
  от минут до часов. Колонка показывает «трек недоступен». Помогает выделенный IP у
  провайдера или ожидание.
- **Перемотки в 0.7.2-hotfix нет:** `ytm-alice seek` отвечает, что штатный плеер её не
  поддерживает. Перемотка с телефона тоже не работает.
- **Веб-панель без пароля.** Ею может управлять любой в локальной сети. Не открывайте её
  в интернет пробросом порта на роутере.
- При установке перезапускается Bluetooth колонки: его службы переходят на отдельную
  шину D-Bus.
- После конца очереди трансляции с телефона похожие треки не подбираются.

## Откат { #rollback }

1. Снимите автозапуск и медиаслой:

    ```sh
    /data/yam/bin/ytm-alice daemon uninstall
    ```

2. Удалите пакет:

    ```sh
    yam remove local/ytm-alice
    ```

3. Перезагрузите колонку: `reboot`.

Первая команда убирает оба скрипта автозапуска из `/etc/init.d` и возвращает штатный
Bluetooth.

## Как это работает { #how }

| Часть | Что делает |
|---|---|
| `ytm-alice serve` | сервис: поиск через API YouTube Music, очередь, веб-панель, команды |
| `ytm-alice-player` | плеер на штатном GStreamer прошивки, громкость общая с Алисой |
| `bt-proxy` | показывает плеер Алисе как Bluetooth-источник, поэтому работают кнопка и «пауза» |
| голос | сервис читает распознанные Алисой фразы и сам выполняет музыкальные команды |
| трансляция | DIAL и протокол YouTube Lounge, как у смарт-ТВ |

Медиаслой `bt-proxy` описан в рецепте [Плееры как Bluetooth](bt-proxy.md).

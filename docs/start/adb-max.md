# Станция Макс — ADB Max

Получение прав root для отладки на Яндекс Станции Макс (`yandexstation_2`, YNDX-0008) без модификации разделов памяти и без записи на диск. Единственное, что требуется на старте — стандартный сетевой доступ по ADB.

```text
uid=0(root) gid=0(root) groups=0(root) context=u:r:kernel:s0
```

!!! warning "Внимание"
    Утилита во время работы временно модифицирует служебные структуры ядра в оперативной памяти и переключает режим SELinux. Сбой во время выполнения оставляет колонку в зависшем состоянии до перезагрузки по питанию. Обязательно прочитайте раздел [«Подводные камни»](#подводные-камни) перед первым запуском.

!!! danger "Это не DNS-метод"
    [DNS-метод](root.md) на Станции Макс **не работает**: здесь установлена платформа Android TV (YaOS_X, Android 9), системный `adbd` собран в режиме production, а команда `adb root` возвращает `adbd cannot run as root in production builds`. Служебных скриптов `activate_adb.sh` и `onboot.sh`, используемых на других Станциях, на Максе нет.

    Здесь описан отдельный путь — запуск отладочной утилиты через пользовательскую сессию ADB.

Инструмент и полное описание исходного кода — в репозитории проекта[^repo].

[^repo]: <https://github.com/amirilivice/yandex-station-2-s905x2-root>

---

## Что понадобится

- Колонка на прошивке **`PPR1.180610.011.20220415`**, ядро `4.9.113-g985a1e6b`;
- Сетевой доступ по ADB к порту 5555;
- Компьютер с установленным `adb`;
- **Android NDK** (рекомендуется версия r26d) и Python 3 — для компиляции утилиты `reader4`.

Прошивку **не обновляйте** до и во время работы: при смене версии ядра адреса памяти становятся недействительными.

---

## 1. Проверьте версию прошивки

Все адреса структур в утилите привязаны к конкретной сборке ядра. На других версиях запуск приведёт к сбою, поэтому перед началом проверьте свойства системы:

```sh
adb shell getprop ro.build.fingerprint
```

Ожидаемый ответ:

```text
Yandex/yandexstation_2/yandexstation_2:9/PPR1.180610.011/20220415:user/release-keys
```

Если значение отличается — **остановитесь**. Адреса потребуется пересчитать из ядра вашей версии (инструкция есть в репозитории автора).

Также проверьте текущий статус:

```sh
adb shell getprop ro.product.device      # yandexstation_2
adb shell uname -a                        # 4.9.113-g985a1e6b
adb shell id                              # uid=2000(shell)
adb shell getenforce                      # Enforcing
```

---

## 2. Подключение по ADB

Работа начинается из стандартной непривилегированной сессии `uid=2000(shell)`:

```sh
adb connect <IP-колонки>:5555
adb devices          # статус: <IP-колонки>:5555    device
adb shell id         # uid=2000(shell) ... context=u:r:shell:s0
```

Особенности этой среды:
* **Каталог `/data/local/tmp` доступен для записи** (системный `/tmp` закрыт).
* **Журнал `dmesg` ограничен** (`kernel.dmesg_restrict`), многие разделы `/proc` и `/sys` возвращают `Permission denied`.

---

## 3. Сборка исполняемого файла

Клонируйте репозиторий с исходниками и соберите бинарник:

```sh
git clone https://github.com/amirilivice/yandex-station-2-s905x2-root
cd yandex-station-2-s905x2-root
python tools/build.py /path/to/android-ndk-r26d
```

Скрипт использует компилятор `armv7a-linux-androideabi21-clang` из NDK и собирает программу `src/reader4` с ключами `-O2 -fPIE -pie -DSHELL`.

Команда, которую необходимо выполнить от имени администратора, указывается **на этапе сборки**:

```sh
python tools/build.py /path/to/ndk \
    --payload "id > /data/local/tmp/who.txt; getenforce >> /data/local/tmp/who.txt"
```

По умолчанию без аргумента `--payload` выполняется безопасный тестовый набор: вывод `id`, статус SELinux и возврат режима в enforcing.

---

## 4. Запуск утилиты

Запуск через автоматический скрипт:
```sh
python tools/build.py /path/to/android-ndk-r26d --device --serial <IP-колонки>:5555
```

Или вручную через консоль ADB:
```sh
adb push src/reader4 /data/local/tmp/reader4
adb shell "chmod 755 /data/local/tmp/reader4"
adb shell "rm -f /data/local/tmp/r4.log; \
  timeout 240 /data/local/tmp/reader4 > /data/local/tmp/r4.log 2>&1; \
  echo RUN_DONE; id; getenforce"
```

**Важные правила запуска:**
1. Перед запуском проверяйте `uptime` — колонка должна проработать не менее трёх минут.
2. Не запускайте утилиту дважды подряд без перезагрузки колонки.

---

## 5. Проверка результата

Посмотрите журнал выполнения:

```sh
adb shell cat /data/local/tmp/r4.log
```

При успешном выполнении в логе появится идентификатор суперпользователя:

```text
uid=0(root) gid=0(root) groups=0(root) context=u:r:kernel:s0
```

Проверка должна выполняться внутри запущенной команды, так как библиотека bionic кэширует `getuid()` на старте процесса.

---

## Возможности и ограничения метода

Права root предоставляются **только для одного запущенного процесса**, а не для системного демона. Как только процесс завершает работу, оболочка снова возвращается в `uid=2000(shell)`.

Процесс выполняется в контексте `u:r:kernel:s0`, что открывает доступ к чтению `/proc/kallsyms`, конфигурации `/proc/config.gz` и блочным устройствам.

**Ограничения:**
* **Разделы `/system`, `/vendor` и `/` нельзя изменить навсегда:** подсистемы AVB 1.1 и dm-verity проверяют криптографическую целостность разделов при старте.
* **Постоянного root-демона нет:** модификация действует только в оперативной памяти во время работы конкретной команды.

---

## Возврат в исходное состояние

Так как утилита **не производит изменений на накопителе флеш-памяти**, простая перезагрузка по питанию возвращает колонку в исходное состояние:

```sh
adb shell reboot
```

После перезагрузки статус SELinux возвращается в стандартный режим:

```sh
adb shell getenforce          # Enforcing
```

Удалите временные файлы после завершения работы:

```sh
adb shell rm -f /data/local/tmp/reader4 /data/local/tmp/r4.log
```

---

## Подводные камни { #подводные-камни }

* Перед запуском сверяйте `uptime` — если колонка ушла в рестарт, старый файл `r4.log` может остаться в каталоге.
* Не запускайте команду повторно без перезагрузки системы.
* Не используйте файлы со сторонних устройств с другими версиями ядра.

---

## Как устроен этот метод

Станция защищена проверками целостности (Android Verified Boot 1.1, dm-verity на системных разделах) и SELinux в режиме enforcing. Модификация разделов на диске заблокирована, поэтому доступ получается исключительно в оперативной памяти без записи на накопитель.

Метод использует особенность драйвера графического ускорителя Mali (`kbase`) при управлении страницами видеопамяти. Через интерфейс выделения памяти отладочная программа получает доступ к адресным структурам ядра в RAM, временно переключает контекст запущенной команды в режим администратора (`uid=0`) и переводит режим SELinux.

Для сборки `4.9.113` (`PPR1.180610.011.20220415`) адреса зафиксированы в коде утилиты. Механизм KASLR (рандомизация адресного пространства) на этой прошивке отключён, поэтому адрес базовой загрузки ядра постоянен (`0x1080000`).

## Отличия от DNS-метода

| Параметр | [DNS-метод](root.md) | Метод Станции Макс |
|---|---|---|
| **Модели** | Лайт, Мини, Миди, Станция 2 | **Станция Макс (YNDX-0008)** |
| **Платформа** | Buildroot / quasar | **Android 9 (YaOS_X)** |
| **Принцип** | Ответ облачной синхронизации | **Драйвер графики Mali (в RAM)** |
| **Результат** | Постоянный `adbd` на порту 5555 | Права root на **один процесс** |
| **Заводской сброс** | Требуется | Не требуется |
| **Изменение прошивки** | Маркеры в `/data/quasar` | Не требуется |
| **После перезагрузки** | Сохраняется | Возврат в заводское состояние |

Полное описание исходного кода утилиты и разбор адаптации под другие сборки ядра доступны в репозитории проекта[^repo].

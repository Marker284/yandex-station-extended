# Шаг 1. Root по сети: подмена DNS

Сетевой ADB с правами `root` — без разборки корпуса, пайки и программатора, примерно
за пятнадцать минут. Способ подходит Мини, Мини 2, Мини 3, Миди, Станции 2, Станции 3,
Стрит, Умному хабу и Лайт первого поколения. В вики и в чате его называют коротко —
DNS-метод.

После этого шага переходите к [шагу 2](ssh.md): SSH и отключение обновлений. Без него
Яндекс может прислать обновление и закрыть доступ.

## Что понадобится

- роутер, в котором можно поменять DNS (Keenetic, OpenWrt, MikroTik, Asus…), **или** второй
  Android-смартфон, раздающий Wi-Fi;
- компьютер в той же сети с утилитой `adb`, инструкция по установке —
  [как поставить](adb.md);
- смартфон с приложением «Дом с Алисой» (или «Яндекс»);
- колонка и её блок питания.

!!! warning "Сброс к заводским настройкам очищает раздел /data"
    Пользовательские настройки и всё, что вы туда ставили, пропадут, а колонку придётся
    заново привязать к аккаунту.

## Инструкция { #dns-unlock }

Выберите способ — оба дают сетевой ADB с root:

=== "Вариант 1. Сервер 179.254.167.126"


    ### 1. Сбросьте колонку к заводским настройкам

    Кнопка и порядок зависят от модели — выберите свою.

    === "Лайт (1-го поколения)"

        1. Отключите кабель питания, подождите несколько секунд и вставьте обратно.
        2. **Сразу после этого** зажмите кнопку паузы (▶‖) и держите 6–10 секунд, пока
           подсветка не станет жёлто-зелёной. Если зажать кнопку до подачи питания,
           сброса не будет.
        3. Отпустите кнопку: подсветка пульсирует голубым, колонка ждёт настройки.

    === "Мини 2, Мини 3, Стрит"

        1. Отключите кабель питания.
        2. Зажмите кнопку отключения микрофона или паузы.
        3. Не отпуская кнопку, вставьте кабель.
        4. Держите 10–15 секунд, пока подсветка не замигает и Алиса не скажет
           о начале сброса.

    === "Лайт 2 (Plum)"

        Только для сборок до 21 октября 2026 года.

        1. Отключите кабель питания.
        2. Зажмите кнопку отключения микрофона и, не отпуская её, подключите питание.
        3. Держите кнопку 10–15 секунд, пока подсветка не замигает и Алиса не скажет
           о начале сброса.

    === "Мини 3 Про"

        1. Отвяжите колонку от аккаунта в приложении и отключите кабель питания.
        2. Зажмите кнопку отключения микрофона и не отпускайте.
        3. Подключите питание: подсветка замигает жёлтым, кнопку всё ещё держите.
        4. Когда жёлтый погаснет, отпустите кнопку.

        Проверено на заводской `factory-12`, см.
        [страницу модели](../devices/station-mini3-pro.md#factory-12).

    === "Миди, Станция 2"

        1. Отключите питание.
        2. Зажмите центральную сенсорную кнопку или кнопку микрофона сзади
           и подключите питание.
        3. Дождитесь звукового сигнала и сообщения о начале сброса.

    Через 1–2 минуты колонка предложит настроить её через приложение.

    ### 2. Начните привязку в приложении — и остановитесь на Wi-Fi

    1. Включите на смартфоне Bluetooth и геолокацию.
    2. «Дом с Алисой» → **«+»** → **«Устройство с Алисой»**.
    3. Дойдите до экрана **«Выберите сеть Wi-Fi и введите пароль»**.

    !!! warning "Нажатие кнопки подключения до смены DNS приведёт к ошибке"
        Не нажимайте «Подключиться» до выполнения шага 3: приложение не сможет связать
        колонку с аккаунтом, и настройку придётся начинать заново.

    ### 3. Включите DNS `179.254.167.126` на роутере

    Колонка должна получить DNS `179.254.167.126`. Выберите свой роутер:

    === "Keenetic"

        **Веб-интерфейс:** «Сетевые правила» → «Домашняя сеть» → «Параметры IP и DHCP» →
        **DNS 1** = `179.254.167.126`, поле **DNS 2** очистите → «Сохранить».

        **Или CLI** — подменяет только нужный домен, остальная сеть не затронута:

        ```text
        ip host quasar.yandex.net 179.254.167.126
        system configuration save
        ```

        Откат после шага 2 — верните прежние DNS в веб-интерфейсе или выполните
        `no ip host quasar.yandex.net` и `system configuration save`.

    === "TP-Link"

        **Веб-интерфейс:** «Дополнительные настройки» → «Сеть» → «DHCP-сервер» →
        **Предпочитаемый DNS-сервер** = `179.254.167.126`, поле **Альтернативный DNS-сервер**
        очистите → «Сохранить». В старом (зелёном) интерфейсе те же поля обычно лежат в
        разделе «DHCP» → «Настройки DHCP».

        Откат после шага 2 — верните прежние значения (обычно поля оставляют пустыми).

    === "OpenWrt"

        Команды выполняются по SSH на роутере. Выберите **один** способ:

        === "Только домены активации"

            Пересылка в dnsmasq только для трёх доменов. Остальные запросы обслуживаются
            как обычно, в том числе через Podkop:

            ```sh
            uci add_list dhcp.@dnsmasq[0].server='/quasar.yandex.net/179.254.167.126'
            uci add_list dhcp.@dnsmasq[0].server='/quasar.yandex.ru/179.254.167.126'
            uci add_list dhcp.@dnsmasq[0].server='/scbh.yandex.net/179.254.167.126'
            uci commit dhcp && /etc/init.d/dnsmasq reload
            ```

            Правила действуют для этих доменов и их поддоменов у всех клиентов dnsmasq,
            а не только у колонки. Запросы клиентов напрямую к другим DNS-серверам этот
            способ не перехватывает.

            Проверено на OpenWrt 24.10.5 с Podkop: Мини 2, прошивка
            `0.369.1.46.4793643989.20261020.299`, и Миди, прошивка
            `0.369.1.46.4778262955.20261013.160`.

            <a id="rollback-openwrt-domains"></a>

            **Откат после шага 2** — удалите только добавленные записи:

            ```sh
            uci -q del_list dhcp.@dnsmasq[0].server='/quasar.yandex.net/179.254.167.126'
            uci -q del_list dhcp.@dnsmasq[0].server='/quasar.yandex.ru/179.254.167.126'
            uci -q del_list dhcp.@dnsmasq[0].server='/scbh.yandex.net/179.254.167.126'
            uci commit dhcp && /etc/init.d/dnsmasq reload
            ```

        === "Все DNS-запросы (DNAT)"

            !!! warning "Правило перехватывает DNS всей локальной сети"
                Podkop и другие настройки DNS после него могут перестать работать. Если в
                сети такое есть, используйте пересылку только доменов активации, а перед
                переходом на неё удалите правило `Quasar-Unlock` по инструкции отката ниже.

            ```sh
            uci add firewall redirect
            uci set firewall.@redirect[-1].name='Quasar-Unlock'
            uci set firewall.@redirect[-1].src='lan'
            uci set firewall.@redirect[-1].proto='tcp udp'
            uci set firewall.@redirect[-1].src_dport='53'
            uci set firewall.@redirect[-1].dest_ip='179.254.167.126'
            uci set firewall.@redirect[-1].dest_port='53'
            uci set firewall.@redirect[-1].target='DNAT'
            uci commit firewall && /etc/init.d/firewall reload
            ```

            <a id="rollback-openwrt-dnat"></a>

            **Откат после шага 2** — удалите все правила `Quasar-Unlock`, даже если правило
            добавляли несколько раз. Цикл проверен через `sh -n`, на роутере отдельно
            не выполнялся:

            ```sh
            while :; do
                section="$(
                    uci show firewall |
                        sed -n "s/^\(firewall\.[^.]*\)\.name='Quasar-Unlock'$/\1/p" |
                        head -n 1
                )"
                [ -n "$section" ] || break
                uci delete "$section" || break
            done
            uci commit firewall && /etc/init.d/firewall reload
            ```

    === "Другой роутер"

        В настройках локальной сети найдите DNS-серверы, которые роутер раздаёт по DHCP:
        **DNS 1** = `179.254.167.126`, **DNS 2** — пусто. Обычно это раздел
        «Локальная сеть» / «LAN» → «DHCP-сервер» (Asus и другие).

        Если DNS там задаётся только для подключения к провайдеру (WAN), это не подойдёт:
        используйте раздачу с Android.

        Откат после шага 2 — верните прежние значения (обычно поле оставляют пустым или
        ставят IP роутера).

    === "Раздача с Android"

        Если роутер не даёт менять DNS:

        1. Раздайте Wi-Fi с одного телефона.
        2. На раздающем телефоне поставьте **DNS Changer** и задайте `179.254.167.126`.
        3. Привязывайте колонку с **другого** телефона к этой точке доступа.

    ### 4. Подключите колонку к Wi-Fi

    Вернитесь в приложение и нажмите **«Подключиться»**. Колонка подключится к сети,
    сходит на сервер разблокировки, помигает и издаст звук готовности.

    ### 5. Зайдите по ADB

    IP колонки посмотрите в списке клиентов роутера.

    ```sh
    adb connect 192.168.1.120:5555      # IP вашей колонки
    adb devices          # должно быть: 192.168.1.120:5555    device
    adb shell            # приглашение «#» — это root
    ```

    ### 6. Сразу переходите к шагу 2

    👉 **[SSH и отключение обновлений](ssh.md)** — сделайте это до того, как вернёте DNS.

    ### 7. Верните обычный DNS { #restore-dns }

    После шага 2 уберите `179.254.167.126` из настроек роутера — команды отката есть на
    вкладке вашего роутера в шаге 3. Доступ сохранится.

    !!! warning "Мини 2: ADB выключается после первой синхронизации с облаком"
        На Мини 2 (`0.369.1.46…299`) Quasar выключает ADB, как только получает настройки
        от настоящего `quasar.yandex.net`: в `/data/quasar/quasar_adb.log` появляется
        `Deactivate adb by quasmodrom config`, порт `5555` закрывается. Маркеры в
        `/data/quasar/` это не спасает. SSH из [шага 2](ssh.md) работает дальше, поэтому
        сделайте шаг 2 до возврата DNS. ADB включается снова по SSH:
        `/system/vendor/quasar/activate_adb.sh --quasmodrom --network activate` — до
        следующей синхронизации, а Quasar делает её при каждом старте.

    - OpenWrt: [только домены активации](#rollback-openwrt-domains) или
      [DNAT](#rollback-openwrt-dnat).

=== "Вариант 2. Свой сервер обновлений на компьютере"

    <a id="local-stand"></a>


    Альтернатива серверу `179.254.167.126`: DNS и HTTPS поднимаются на вашем компьютере
    (Windows, Linux или macOS), и колонка получает **настоящий ответ Яндекса**, в который
    добавлено `adbd.remoteActivation`. Никаких внешних сервисов — только свой ПК и роутер
    со сменным DNS.

    **Чем отличается от варианта 1:** первый вариант обращается к внешнему серверу разблокировки.
    Второй — полностью локальный: вы видите запросы колонки, можете обновлять прошивку и
    включать ADB повторно после сброса. Подходит для тех, кто не хочет зависеть от чужого сервера.

    ### 1. Подготовьте ПК

    Сервер и скрипты запуска для всех трёх систем лежат в
    [репозитории lite-kit](https://github.com/krevetkqqq/lite-kit), там же установщик
    прошивок. Порты 53 (UDP и TCP), 80 и 443 на компьютере должны быть свободны.

    === "Windows 10/11"

        1. Установите [Python 3.8 или новее](https://www.python.org/downloads/),
           отметив галочку **Add python.exe to PATH**.
        2. Склонируйте репозиторий:

            ```powershell
            git clone https://github.com/krevetkqqq/lite-kit C:\lite-kit
            ```

            Без git — скачайте
            [ZIP-архив](https://github.com/krevetkqqq/lite-kit/archive/refs/heads/main.zip)
            и распакуйте в `C:\lite-kit`.
        3. Освободите порт 53: его иногда занимает служба «Общий доступ к подключению
           к Интернету».

    === "Linux"

        1. Поставьте зависимости и склонируйте репозиторий:

            ```sh
            sudo apt install dnsmasq python3 openssl dnsutils
            git clone https://github.com/krevetkqqq/lite-kit ~/lite-kit
            ```

        2. Освободите порт 53: его обычно занимают `systemd-resolved` или `avahi`.

    === "macOS"

        1. Поставьте зависимости и склонируйте репозиторий:

            ```sh
            brew install dnsmasq
            git clone https://github.com/krevetkqqq/lite-kit ~/lite-kit
            ```

        2. Убедитесь, что порт 53 свободен.

    ### 2. Выберите прошивку

    Сервер умеет раздавать колонке нужную сборку: если в `firmware/` лежит `.zip`,
    а версия колонки отличается — он сам предложит обновление.

    Если на колонке уже стоит нужная версия (или файл прошивки уже лежит
    в `firmware/`), ничего выбирать не нужно — переходите к запуску сервера обновлений.

    **Рекомендуемые версии прошивок** — для моделей из
    [таблицы совместимости](#compat-local) ниже; на остальных вариант 2 не проверялся:

    | Модель | Версия |
    |---|---|
    | Лайт 1 (`yandexmicro`) | `0.369.1.46.4778262442.20261013.297` (сборка от 13.10.2026) |
    | Мини 1 (`yandexmini`) | сборка 2025 года: `1.305.4.16.3237824040.20250721` |
    | Мини 2 (`yandexmini_2`) | `0.369.1.46.4778262943.20261013.299` (сборка от 13.10.2026) |
    | Мини 3, Лайт 2, Миди, Станция 2 и остальные | желательно **последняя сборка до обновления 20–21 октября 2026** |

    Более новые сборки сертификат не принимают — ADB через `get_sync_info`
    на них не поднимется.

    !!! tip "Мини 2 на сборках после 21 октября 2026 года"
        Сборка `0.372.1.13.4794674157.20261021.302` своему серверу не доверяет: на `443`
        колонка обрывает TLS алертом `unknown_ca` (48), до `get_sync_info` дело не доходит.
        В логе сервера этого не видно, только в `tcpdump` на его интерфейсе. Сброс возвращает
        factory-образ `0.17.1.32.1145264292.20211203.factory-3`, а он серверу доверяет: дальше
        как у Лайт 1 ниже, сервер отдаёт `.46` из `firmware/yandexmini_2/`. Проверено на Мини 2
        (YNDX-00020): откат на `0.369.1.46.4778262943.20261013.299`, ADB с root, затем
        [шаг 2](ssh.md).

    Лайт 1 со сборкой `0.369.1.50…` тоже открывается, но прошивка откатится на `.46`:
    сервер сам отдаст её колонке во время настройки. Это несколько лишних минут и
    работает только здесь, на своём сервере обновлений.

    ??? note "Почему на этой сборке нужен именно свой сервер"
        Сброс грузит factory-образ из раздела `recovery`
        (`0.5.1.20.1624028365.20230208.factory-4`), и он серверу обновлений доверяет. После
        `POST /register` factory-образ не запрашивает `get_sync_info`, а ждёт обновления:
        сервер отдаёт ему `.46` из `firmware/`, колонка скачивает 67 МБ, ставит прошивку и
        через несколько минут перезагружается. Уже сборка `.46` запрашивает `get_sync_info`
        и включает ADB с root.

        Поэтому сервер, который на `check_updates` отвечает только `{"hasUpdate":false}`,
        здесь не годится: factory-образ так и останется ждать обновления.

        Проверено на Лайт 1 с `0.369.1.50…`: откат на
        `0.369.1.46.4778262442.20261013.297`, ADB с root, дальше [шаг 2](ssh.md). Отдаёт ли
        прошивку для отката сервер `179.254.167.126` из варианта 1, не проверялось.

    !!! warning "Дождитесь завершения скачивания и установки"
        После начала скачивания (в логе `[OTA] отдано …`) не выдёргивайте питание: скачивание
        67 МБ, установка и перезагрузка занимают несколько минут. Признак завершения —
        `[SYNC-REAL→] … adbd=on` в логе. Если прервать, factory-образ в `recovery` цел,
        но процесс придётся начать заново.

    Скачать и положить в `firmware/<версия>.zip` можно установщиком:

    === "Windows"

        ```powershell
        .\install-firmware.ps1                 # меню: платформа -> версия (по цифрам)
        .\install-firmware.ps1 -List           # только список платформ
        .\install-firmware.ps1 -Platform yandexmicro -Version 0.369.1.46.4778262442.20261013.297
        ```

    === "Linux и macOS"

        ```sh
        ./install-firmware.sh
        ```

    Уже проверенные версии в меню помечены `<-- проверено (ADB работает)`.

    ### 3. Запустите сервер обновлений

    === "Windows"

        ```powershell
        cd C:\lite-kit
        .\start.ps1        # сам запросит права администратора
        ```

    === "Linux и macOS"

        ```sh
        cd ~/lite-kit
        sudo ./start.sh
        ```

    Скрипт напечатает **IP этого ПК** и проверит DNS. В логе (`log\server.log`,
    `log\yandex.log`, `log\local.log`, `log\dns.log`) видно каждый запрос колонки.

    ### 4. Включите DNS на роутере

    DNS 1 = **IP компьютера с сервером обновлений**, DNS 2 — пусто. Способы те же, что в
    [варианте 1](#dns-unlock) (вкладки шага 3), только вместо `179.254.167.126` — IP
    компьютера.

    Проверка с ПК:

    ```sh
    nslookup quasar.yandex.net <IP-роутера>   # должен вернуть IP компьютера
    ```

    ### 5. Привяжите колонку в приложении

    Действия те же, что в варианте 1: сброс → «Дом с Алисой» → «+» → «Устройство с Алисой»
    → дойти до выбора Wi-Fi. **DNS включайте только на экране выбора сети** — иначе
    приложение не сможет привязать колонку.

    **Особенность при настройке через телефон:**
    если телефон подключён к той же Wi-Fi-сети, что и колонка, запросы приложения к
    `quasar.yandex.net` тоже уходят на сервер обновлений. Приложение не принимает его
    сертификат (в логе сервера каждые пару секунд появляется ошибка `alert certificate unknown`),
    и настройка срывается — например, с сообщением «Не получилось подключить колонку по Bluetooth».
    Выключите на телефоне Wi-Fi, оставьте мобильный интернет и Bluetooth, а сеть и пароль
    для колонки введите вручную. Тогда DNS можно включить и до сброса. Проверено на iPhone с Лайт 1.

    ### 6. Проверьте ADB

    ```sh
    adb connect <IP-колонки>:5555
    adb shell id          # uid=0(root)
    ```

    Если порт закрыт:

    ```powershell
    .\check.ps1           # Windows
    ```
    ```sh
    ./check.sh            # Linux / macOS
    ```

    В логе сервера обновлений должно быть:

    ```text
    >>> [SYNC-REAL→] payload …, adbd: config.system_config.adbd=on, …, top.adbd=on
    ```

    Пока не вернули DNS — переходите к [шагу 2](ssh.md): SSH и отключение обновлений.
    Сервер сам прошивку не навязывает: он отдаёт только ответ Яндекса (плюс `adbd`),
    а обновления закрываются на [шаге 2](ssh.md).

## Если не получилось

| Симптом | Что делать |
|---|---|
| Приложение пишет «Не удалось подключиться к Wi-Fi» | DNS включили слишком рано. Уберите DNS, сбросьте колонку и пройдите привязку заново, включая DNS только на экране ввода пароля Wi-Fi |
| Колонка в сети, но порт 5555 закрыт (`Connection refused`) | Отключите на роутере фильтрацию DNS (Яндекс.DNS, AdGuard и другие) и передёрните питание колонки. Проверка с компьютера: `nslookup quasar.yandex.net` должен вернуть `179.254.167.126` |
| `adb connect` пишет `unable to connect` | Компьютер и колонка должны быть в одной сети, не в гостевой с изоляцией клиентов. Проверьте доступность: `ping <IP_колонки>` |

## Как это работает

1. Сброс возвращает колонку в заводское состояние: `/data` очищен.
2. При первом подключении колонка запрашивает настройки у `quasar.yandex.net`. С DNS
   `179.254.167.126` запрос уходит на сервер разблокировки.
3. Сервер отвечает настройками, в которых сетевой ADB включён.
4. Прошивка создаёт маркеры `/data/quasar/activate_adb_quasmodrom` и
   `/data/quasar/activate_network_adb` и запускает `adbd` на порту **5555**.
5. При каждой загрузке `onboot.sh` вызывает `activate_adb.sh check`: пока маркеры на месте,
   ADB поднимается сам — DNS больше не нужен. На Мини 3 это не так: после возврата DNS ADB
   выключается, см. [раздел про возврат DNS](retail-ca-mini3.md#adb-after-dns).

    Шаг 1. Root на Станции Мини 3: retail CA и маркеры из factory¶

    Способ для Станции Мини 3 (bergamot) после обновления 21 октября 2026 года, когда DNS-метод перестал работать. Колонка загружается в factory mode, в retail-разделе правится только CA-бандл, а в /data кладутся маркеры сетевого ADB и конфиг Wi-Fi. После normal-загрузки ADB с root поднимается сам, пока DNS указывает на сервер обновлений. Постоянный вход — SSH из шага 2. После возврата DNS настоящий Яндекс выключает ADB, как описано в шаге 7.

    Основа — гайд для Лайт 2: порядок тот же, ниже — с поправками под Мини 3.

    После этого шага переходите к шагу 2: SSH и отключение обновлений.

    Проверено на: Станция Мини 3 (bergamot) с factory-сборкой 0.6.1.4.…factory-6 от 11.11.2024, октябрь 2026.

    Чем Мини 3 отличается от Лайт 2¶

    Лайт 2 (plum) Мини 3 (bergamot)
    factory-образ отдельный раздел factory отдельного раздела нет: образ лежит в recovery (mtd6, ramdisk 27,7 МБ), загрузка с rootfstype=ramfs
    system mtd3, UBI-том rootfs то же: mtd3, UBI-том rootfs
    UBI в factory нужен ubiattach -m 3 не нужен: в cmdline есть ubi.mtd=system, ubi0 уже поднят
    CA /system/vendor/quasar/certs/ca-certificates.crt тот же файл, а /system/vendor/quasar/ca-certificates.crt — симлинк на него
    factory-сборка — 0.6.1.4.…factory-6 от 11.11.2024 или 0.4.1.39.…factory-4 от 21.10.2024; в обеих ещё есть корень AAA
    normal-загрузка upgrade_step=1, boot_to_recovery=0 то же; в factory upgrade_step=2
    OTA S01swupdate + swupdate в .50 нет ни S01swupdate, ни swupdate: применяет device_ota_update.sh → apply_packed_ota, подпись проверяется по ota_script.pub
    Wi-Fi — данные сети только в /data/wpa_supplicant.conf; без файла после перезагрузки колонка никуда не подключается

    В factory корневая файловая система живёт в памяти (ramfs) — правки в ней не сохраняются. В retail / — ubifs на mtd3, смонтирован ro, но dm-verity нет: mount -o remount,rw / и sync пишут на флеш, и правки переживают перезагрузку.

    Что понадобится¶

    • компьютер с adb в одной сети с колонкой;
    • свой сервер обновлений на компьютере — локальный HTTPS-сервер, который отвечает на get_sync_info конфигом с adbd (remoteActivation, network), а на check_updates — {"hasUpdate":false}. Его сертификат должен строиться до корня AAA Certificate Services (цепочка eMudhra: лист ← EM OV TLS CA - G3C ← AAA). Так устроен, например, eQuasar; остальные запросы (в первую очередь /register) сервер должен проксировать в настоящий Яндекс — для eQuasar нужна строка resolver;
    • DNS: подмена на роутере или хотспот с компьютера (общий доступ к интернету в Windows отдаёт колонке DNS = IP компьютера);
    • корень AAA: contrib/packages/aaa-certificate-services.pem.

    0. Проверка: жив ли factory-образ¶

    Сброс кнопкой (зажать кнопку отключения микрофона и подать питание, держать 10–15 с) грузит factory-образ из recovery. После получения shell (шаг 1):

    cat /proc/cmdline                          # rootfstype=ramfs, без root=
cat /system/vendor/quasar/version_full

    Ожидается factory-сборка: 0.6.1.4.…factory-6 или 0.4.1.39.2634333263.20241021.factory-4 (по проходу автора). Если видно 0.369.1.50… — factory-образ обновлён вместе с retail, войти этим способом нельзя, дальше не идите.

    1. Сервер обновлений и вход в сервисный режим¶

    1. Поднимите свой сервер обновлений на компьютере с настройкой resolver. Настройте DNS на роутере или через хотспот компьютера, см. пример для Keenetic.
    2. Обесточьте колонку, зажмите кнопку отключения микрофона, подайте питание и держите 10–15 с, пока подсветка не замигает.
    3. В приложении «Дом с Алисой» добавьте колонку и дайте ей Wi-Fi с нужным DNS. Приложение может сообщить, что настроить не удалось, — это нормально.
    4. Убедитесь, что в логе сервера есть POST /register с кодом 200, а за ним /get_sync_info и /check_updates, и подключитесь по ADB:
    adb connect <IP_колонки>:5555
adb shell id

    Ожидается uid=0(root).

    На macOS, если nc -z <IP_колонки> 5555 проходит, а adb connect пишет No route to host, adb блокирует защита «Локальная сеть» — см. установку ADB.

    Сброс кнопками стирает раздел /data

    Вместе с ним исчезают старые маркеры и /data/quasar/data/user_config.dat. Всё нужное создаётся заново на шагах 4–5.

    eQuasar: resolver для /register¶

    Factory-прошивка сначала регистрируется: POST /register с кодом активации из приложения. eQuasar перехватывает только get_sync_info и check_updates, остальное проксирует директивой proxy_pass https://$host…, а для имени из переменной nginx нужен resolver. Без него /register получает 502 (в журнале error.log — no resolver defined to resolve quasar.yandex.net), приложение пишет об ошибке (например, что не удалось подключить колонку по Bluetooth), колонка уходит из Wi-Fi и до get_sync_info не доходит.

    Добавьте строку в блок server { listen 443 ssl; … } файла copymetoroot/etc/nginx/sites-enabled/quasar и пересоберите сервер обновлений (docker compose up -d --build):

    resolver 77.88.8.8 8.8.8.8 ipv6=off valid=300s;

    Резолвер — публичный, не DNS роутера: тот отдаёт для quasar.yandex.net адрес сервера, и запрос зациклится. С ним регистрация проходит, и Алиса говорит, что настройка завершена и осталось обновить прошивку. Обновления не будет: на check_updates отвечает локальный сервер.

    DNS на Keenetic¶

    В CLI роутера (веб-интерфейс <http://<IP_роутера>/a>; из Entware-shell — ndmc -c "…"):

    ip host quasar.yandex.net <IP_сервера>
ip host quasar.yandex.ru <IP_сервера>
ip host scbh.yandex.net <IP_сервера>
ip host strm.yandex.ru 127.0.0.1
ip host rpc.alice.yandex.net 127.0.0.1
ip host uniproxy.alice.yandex.net 127.0.0.1
ip host alice.yandex.net 127.0.0.1
ip host alice-ats.yandex.net 127.0.0.1
ip host alice-ats-test.yandex.net 127.0.0.1

    Откат — после шага 2, теми же строками с no и без адреса: no ip host quasar.yandex.net и так далее.

    2. Разметка и монтирование retail¶

    cat /proc/mtd              # system = mtd3, recovery = mtd6
ubinfo -a                  # ubi0, том rootfs
mkdir -p /mnt/retail
mount -t ubifs -o rw ubi0:rootfs /mnt/retail
df -h /mnt/retail

    ubiattach не нужен — ubi0 поднимает ядро (ubi.mtd=system в cmdline). Если тома нет, тогда выполните ubiattach /dev/ubi_ctrl -m 3 и возьмите номер UBI из ubinfo -a.

    Проверьте, что смонтирован именно retail:

    cat /mnt/retail/system/vendor/quasar/version_full; echo

    3. Замена CA¶

    В сборке .50 файл в quasar/ — симлинк, поэтому сохраняйте и правьте цель, а не ссылку:

    Q=/mnt/retail/system/vendor/quasar
D=$Q/certs
ls -l $Q/ca-certificates.crt $D/ca-certificates.crt
grep -c 'BEGIN CERTIFICATE' $D/ca-certificates.crt
grep -c 'MIIEMjCCAxqgAwIBAgIBATANBgkqhkiG9w0BAQUFADB7MQswCQYDVQQGEwJHQjEb' $D/ca-certificates.crt
cp -a $D/ca-certificates.crt $D/ca-certificates.crt.orig
mkdir -p /bkupgrade/data/local/tmp
cp $D/ca-certificates.crt /bkupgrade/data/local/tmp/ca.cur

    В .50 ожидается 122 сертификата, а второй grep (первая строка сертификата AAA) — 0: корень из бандла убран.

    Заберите файл на компьютер, допишите в конец корень AAA и верните. Команды запускайте в каталоге, где лежит aaa-certificate-services.pem:

    adb pull /bkupgrade/data/local/tmp/ca.cur retail-ca.pem
$p='retail-ca.pem'
$ca=[IO.File]::ReadAllText($p).TrimEnd()
[IO.File]::WriteAllText($p, $ca + "`n" + (Get-Content aaa-certificate-services.pem -Raw).TrimEnd() + "`n")
adb push retail-ca.pem /bkupgrade/data/local/tmp/ca.new

    adb pull /bkupgrade/data/local/tmp/ca.cur ca.cur
printf '%s\n%s\n' "$(cat ca.cur)" "$(cat aaa-certificate-services.pem)" > retail-ca.pem
adb push retail-ca.pem /bkupgrade/data/local/tmp/ca.new

    Снова на колонке (в adb shell, переменные Q и D — как выше):

    cp /bkupgrade/data/local/tmp/ca.new $D/ca-certificates.crt
chmod 0644 $D/ca-certificates.crt
chown 0:0 $D/ca-certificates.crt
sync
grep -c 'BEGIN CERTIFICATE' $D/ca-certificates.crt
sha256sum $D/ca-certificates.crt

    Ожидается 123 сертификата, а файл длиннее исходного ровно на 1517 байт — размер aaa-certificate-services.pem. Хеш зависит от сборки: по наблюдению автора исходный бандл у .117 и у прежней сборки разный.

    Сборка Исходный бандл (SHA-256) После склейки (SHA-256)
    0.369.1.50.4794652521.20261021.117 5c6138b74904e2b4cddb097d5890912157bff9ecae1f1f21e9f260946ad90b1e 966eb46c99b9952a016f2af43828b807d1fa7baec6c4e2fc91edb61414e0fcd3
    прежний вариант гайда (номер сборки не записан) — 737b5c4acabcadca46842a90cb7ede2acc31bb8ba4664167864d1697d73e8bf4

    Если вашей сборки нет в таблице, проверьте на компьютере, что новый файл — ровно старый плюс корень AAA (Linux / macOS, в каталоге со склейкой):

    cat ca.cur aaa-certificate-services.pem | cmp - retail-ca.pem && echo OK

    Если сертификатов не 123, размер вырос не на 1517 байт или cmp нашёл разницу — не перезагружайте колонку. Восстановите исходный файл по разделу восстановление или повторите склейку.

    Не проверяйте бандл грепом по имени субъекта: в PEM оно закодировано в base64, поэтому grep 'AAA Certificate Services' даёт ноль и на пропатченном файле. Считайте сертификаты, сверяйте хеш, а наличие корня ищите по первой строке его base64, как показано выше.

    4. Маркеры ADB в /data¶

    /data — ссылка на /bkupgrade/data, писать можно прямо туда:

    mkdir -p /bkupgrade/data/quasar
touch /bkupgrade/data/quasar/activate_adb_quasmodrom
touch /bkupgrade/data/quasar/activate_network_adb
ls -l /bkupgrade/data/quasar/activate_*

    Проверьте, что логика срабатывает:

    sh /system/vendor/quasar/activate_adb.sh check
cat /data/quasar/quasar_adb.log

    Должно быть Activation file exists. Activate adb.

    Маркеры вне каталога /data/quasar не сработают

    В adb_options.inc маркеры — /data/quasar/activate_adb_* (через слэш). onboot.sh при каждой загрузке чистит /data/quasar_activate_adb_* (через подчёркивание, в корне /data) — это старая схема, такие файлы не помогают. Кладите только в /data/quasar/.

    5. Wi-Fi в /data¶

    Без этого после перезагрузки колонка никуда не подключится: данные сети приложение записывает только по завершённой настройке.

    Если /register прошёл успешно, файл уже создан с вашей сетью, но с update_config=1. Для eQuasar требуется настройка resolver. Проверьте файл и поменяйте только этот параметр:

    grep -E 'update_config|ssid|key_mgmt' /bkupgrade/data/wpa_supplicant.conf
sed -i 's/^update_config=1$/update_config=0/' /bkupgrade/data/wpa_supplicant.conf
chmod 600 /bkupgrade/data/wpa_supplicant.conf

    Если файла нет — создайте его целиком:

    cat > /bkupgrade/data/wpa_supplicant.conf <<'EOF'
ctrl_interface=/var/run/wpa_supplicant
update_config=0

network={
    ssid="SSID"
    psk="PASSWORD"
    key_mgmt=WPA-PSK
    priority=1
}
EOF
chmod 600 /bkupgrade/data/wpa_supplicant.conf

    update_config=0 обязателен: с 1 wpa_supplicant сам перезапишет файл своим состоянием и выкинет сети, добавленные правкой файла. Две сети — два блока network={}, к какой подключаться, решает priority.

    6. Возврат в normal¶

    fw_printenv upgrade_step boot_to_recovery
sync
mount -o remount,ro /mnt/retail
umount /mnt/retail

    Если upgrade_step=2 — выставьте normal-загрузку и перезагрузитесь:

    fw_setenv upgrade_step 1
fw_setenv boot_to_recovery 0
fw_printenv upgrade_step boot_to_recovery
reboot

    7. Проверка normal-загрузки¶

    IP колонки — в списке клиентов роутера.

    adb connect <IP_колонки>:5555
adb shell cat /proc/cmdline                       # root=ubi0:rootfs rootfstype=ubifs
adb shell cat /system/vendor/quasar/version_full
adb shell cat /data/quasar/quasar_adb.log

    ADB поднимается сам: маркеры → activate_adb.sh check → yandex-debugctl adb-net.

    ADB после возврата DNS¶

    ADB держится, пока на get_sync_info отвечает сервер обновлений. Когда DNS возвращён, настоящий Яндекс присылает конфиг без adbd, и прошивка вызывает activate_adb.sh … deactivate: маркеры удаляются, adbd останавливается. В /data/quasar/quasar_adb.log:

    Reset network flag for adb
Deactivate adb by quasmodrom config

    Поэтому DNS возвращайте только после шага 2: SSH из /etc/init.d/S99zdropbear от маркеров не зависит. В этом проходе chattr +i из шага 2 не ставился, поэтому защита маркеров от удаления здесь не проверена. ADB при необходимости включается из SSH; после перезагрузки синхронизация с Яндексом снова его выключит:

    sh /system/vendor/quasar/activate_adb.sh --quasmodrom --network activate
sh /system/vendor/quasar/activate_adb.sh --quasmodrom --network deactivate   # выключить

    8. Закрепление: обновления и SSH¶

    Дальше — обычный шаг 2: SSH и отключение обновлений, сразу, пока есть ADB и DNS ещё указывает на сервер обновлений. Dropbear из contrib/bin (armhf) на Мини 3 подходит.

    Если файлы копировались через Windows, утилита busybox может спотыкаться о переводы строк CRLF (set: illegal option). Перед запуском уберите их на колонке: tr -d '\r' < /data/opt/yandex-noupdate.sh > /data/opt/noupdate.sh.

    9. Страховка на случай перепрошивки разделов¶

    OTA переписывает mtd0–mtd4 целиком, поэтому правки в system (CA, S99zdropbear) при перепрошивке пропадут, а /data — нет. Держите копии в /data:

    mkdir -p /data/opt/ca
cp /system/vendor/quasar/certs/ca-certificates.crt /data/opt/ca/ca-certificates.crt
cp /etc/init.d/S99zdropbear /data/opt/S99zdropbear

    и скрипт /data/opt/restore-system.sh, который вернёт их одной командой:

    #!/bin/sh
mount -o remount,rw / || exit 1
cp /data/opt/ca/ca-certificates.crt /system/vendor/quasar/certs/ca-certificates.crt
chmod 0644 /system/vendor/quasar/certs/ca-certificates.crt
cp /data/opt/S99zdropbear /etc/init.d/S99zdropbear
chmod +x /etc/init.d/S99zdropbear
sync
mount -o remount,ro /
sh /data/opt/yandex-noupdate.sh
/etc/init.d/S99zdropbear start
pidof dropbear

    Восстановление исходного CA¶

    Из factory mode (шаги 1–2):

    Q=/mnt/retail/system/vendor/quasar
mount -t ubifs -o rw ubi0:rootfs /mnt/retail
cp -a $Q/certs/ca-certificates.crt.orig $Q/certs/ca-certificates.crt
sync
mount -o remount,ro /mnt/retail
umount /mnt/retail

    Если что-то не получилось¶

    • grep 'AAA Certificate Services' даёт 0. Так и должно быть: в PEM имя закодировано. Считайте сертификаты и сверяйте хеш.
    • ubiattach пишет, что устройство уже подключено. В factory на Мини 3 ubi0 уже поднят через ubi.mtd=system. Смонтируйте его том.
    • После перезагрузки колонка не подключается ни к одной сети. Нет /data/wpa_supplicant.conf (или в нём update_config=1, и файл перезаписан). Пропишите конфиг, задайте chmod 600 и перезагрузите.
    • Добавили сеть, а она исчезла. Параметр update_config=1 перезаписал файл. Укажите 0 и добавляйте сети правкой файла, а не через wpa_cli на работающей системе.
    • Точка доступа вещает WPA3, колонка не подключается. Проверьте режим через wpa_cli -i wlan0 scan_results: если во флагах [WPA2-PSK-CCMP], укажите key_mgmt=WPA-PSK. Стандарт SAE в wpa_supplicant 2.9 есть, но требует поддержки 802.11w драйвером — на вендорных драйверах Amlogic её часто нет.
    • Каталог /data/local/tmp отсутствует. В factory-образе такого пути нет. Используйте /bkupgrade/data/local/tmp.
    • Скрипт падает с ошибкой set: illegal option. Это вызвано переводами строк CRLF: выполните tr -d '\r' < in > out.
    • После сброса кнопками всё пропало. Сброс очищает раздел /data: маркеры, настройки Wi-Fi и ключи SSH. Раздел system при этом остаётся вместе с пропатченным CA, поэтому сервер обновлений снова предоставит доступ к ADB в factory mode, а /data/opt восстанавливается по шагам 4–5 и шагу 2.

    Что в итоге¶

    • SSH на порту 2222 стартует сам из /etc/init.d/S99zdropbear — это постоянный вход.
    • ADB с root на каждой загрузке .50, пока DNS указывает на сервер обновлений: маркеры в /data/quasar/ плюс adbd в /data/quasar/data/user_config.dat. После возврата DNS Яндекс выключает ADB, как описано в шаге 7.
    • Обновления закрыты: подменённый ota_script.pub, заглушённый device_ota_update.sh, убранный updatesd.
    • Если OTA всё же прошьётся, S99zdropbear и пропатченный CA пропадут вместе с system, а /data уцелеет. Если маркеры ещё на месте (DNS на сервере обновлений), ADB поднимется сам, и restore-system.sh вернёт CA и SSH одной командой; если нет — заново с шага 1.
